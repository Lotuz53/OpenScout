# OpenScout AI Stage B 统一用户任务脚本

本脚本与 `research-protocol.md` v1.0 配套使用。主持人不得临场改写任务或提供答案。

## 开始前

1. 确认参与者已阅读并同意 `consent-and-redaction.md`。
2. 分配下一个未使用的编号 `P01`—`P10`；不要记录姓名、邮箱或 GitHub 用户名。
3. 确认浏览器使用公开仓库数据，不要求参与者登录 GitHub 或提供任何凭据。
4. 确认 OpenScout 的目标环境可访问，并准备好三个公开仓库：
   `langgenius/dify`、`infiniflow/ragflow`、`labring/FastGPT`。

## 逐字任务说明

“请把自己当作正在为一个需要选择开源 AI 应用平台的团队做快速初筛。请在 OpenScout
中找出：一个最近版本或文档支持的能力事实；一个来自 Issue 或评论的社区信号；以及
两个产品之间一个有证据支持的差异。最后导出一份报告，并用不超过三句话给出下一步
建议。每个事实或统计都要能打开对应的 GitHub 证据。你有 15 分钟，可以按自己习惯
完成，不需要得到某个预设答案。”

开始计时后，主持人只观察并记录：

- 参与者是否完成仓库/工作台配置；
- 打开的证据链接数量；
- 是否导出报告；
- 阻塞发生在哪个阶段；
- 参与者宣布完成或达到 900 秒时的时间。

## 允许的主持人回应

- “请继续按照任务要求完成即可。”
- “如果页面没有响应，请告诉我，我会记录为产品问题。”
- “你可以在任何时候停止；我会记录当前状态。”

## 禁止的主持人回应

- 不推荐查询词、产品、过滤条件、证据链接或报告结论；
- 不替参与者点击、不代为输入答案、不替换失败场次；
- 不解释产品应有行为来掩盖真实故障；
- 不要求登录 GitHub、不索取 token、不打开私有仓库。

## 结束问题

“如果下周还有类似的公开 GitHub 产品研究任务，你愿意再次使用 OpenScout 吗？”

记录 `yes`、`no` 或 `unsure`，随后告知参与者可以撤回本次记录。
